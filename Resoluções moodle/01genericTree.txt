NoArvore* criar_no(const char *nome) {
    NoArvore *novo = (NoArvore*) malloc(sizeof(NoArvore));
    strcpy(novo->nome, nome);
    novo->primeiro_filho = NULL;
    novo->proximo_irmao = NULL;
    return novo;
}
Imagine que cada chamada de criar_no fabrica uma "caixinha" isolada na memória com duas tomadas vazias (NULL).

Se criarmos três caixinhas (A, B e C), temos apenas isso flutuando na memória:

Plaintext
[ A ]                  [ B ]                  [ C ]
 ├── filho: NULL        ├── filho: NULL        ├── filho: NULL
 └── irmao: NULL        └── irmao: NULL        └── irmao: NULL
Até aqui, não existe árvore, não existe pai e não existe filho. São só três blocos separados.

Passo 2: Como adicionar_filho conecta as caixinhas
Agora vamos fazer A ser pai de B, e depois A ser pai de C. Olhe as duas linhas da função com muita atenção:

C++
void adicionar_filho(NoArvore *pai, NoArvore *filho) {
    filho->proximo_irmao = pai->primeiro_filho; // Linha 1
    pai->primeiro_filho = filho;                // Linha 2
}
Operação 1: adicionar_filho(A, B)
Atualmente, A->primeiro_filho é NULL.

Linha 1: B->proximo_irmao recebe o que está em A->primeiro_filho (que é NULL).

Linha 2: A->primeiro_filho passa a apontar para B.

Estado da memória agora:

Plaintext
[ A ]
 ├── filho ──► [ B ]
 └── irmao:     ├── filho: NULL
      NULL      └── irmao: NULL
Operação 2: adicionar_filho(A, C) (Aqui está o segredo!)
Queremos que C também seja filho de A. Mas A só tem um ponteiro para filhos (primeiro_filho), e ele já está ocupado apontando para B!

Como A guarda C sem perder B? Ele coloca C na frente e manda C "segurar a mão" de B:

Linha 1: C->proximo_irmao = A->primeiro_filho;
(Como A->primeiro_filho apontava para B, agora C->proximo_irmao aponta para B!)

Linha 2: A->primeiro_filho = C;
(Agora A aponta direto para C).

Estado da memória agora:

Plaintext
[ A ]
 ├── filho ──► [ C ]
 └── irmao:     ├── filho: NULL
      NULL      └── irmao ──────► [ B ]
                                   ├── filho: NULL
                                   └── irmao: NULL
Olhe para o desenho acima e responda: Quem é o pai de B?
No código, B não tem um ponteiro chamado pai, mas logica e estruturalmente, B é filho de A porque você chega em B descendo pelo primeiro_filho de A (C) e andando para o lado pelo proximo_irmao (B).

É exatamente por isso que dizemos que A->primeiro_filho aponta para uma lista encadeada de filhos: C -> B -> NULL. Todos os nós nessa corrente horizontal estão no mesmo nível e pertencem ao mesmo pai (A).

Passo 3: Adicionando um neto (D filho de B)
Para fechar o entendimento, imagine agora adicionar_filho(B, D).
O ponteiro B->primeiro_filho estava NULL. Ele passa a apontar para D:

Plaintext
[ A ]  (Nível 0)
 ├── filho ──► [ C ]  (Nível 1)
                ├── filho: NULL
                └── irmao ──────► [ B ]  (Nível 1)
                                   ├── filho ──► [ D ]  (Nível 2)
                                   └── irmao:     ├── filho: NULL
                                        NULL      └── irmao: NULL
