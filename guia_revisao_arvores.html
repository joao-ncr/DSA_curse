1. Conceitos-base — direto ao avançado

Atenção — convenção

Não existe uma única definição de altura/profundidade entre os livros. A mais comum (Cormen, Drozdek) é altura(nó folha) = 0 e altura(árvore vazia) = -1, com profundidade(raiz) = 0. Se o enunciado da prova disser "altura = número de níveis", a raiz sozinha já vale 1. Leia a definição no enunciado antes de responder.

GrandezaFórmula (raiz = nível 0)
Nós no máximo no nível k2^k
Nós no máximo em árvore de altura h2^(h+1) - 1
Altura mínima para n nós (balanceada)ceil(log2(n+1)) - 1
Altura máxima para n nós (degenerada)n - 1
Arestas de qualquer árvore com n nósn - 1

Hierarquia de tipos (pegadinha de nomenclatura)

Perfeita (todos os níveis cheios) ⊂ Completa (todos os níveis cheios exceto o último, preenchido da esquerda p/ direita) ⊂ Cheia (todo nó tem 0 ou 2 filhos, nunca 1). Toda perfeita é completa e cheia; a volta não vale — uma árvore pode ser cheia sem ser completa.

Grau: em árvore binária é sempre ≤ 2 por definição, não precisa calcular. Em árvore genérica (a dos seus labs, com primeiro_filho/proximo_irmao) o grau de cada nó é livre — por isso o grau_maximo do lab 1/2 faz sentido só lá.

2. Árvore genérica: representação filho-mais-velho / irmão-mais-novo

Essa é a estrutura de todos os seus labs 1–3 e das questões "sistema de arquivos", "menu de navegação" (lab 3 q1), "taxonomia biológica" (lab 3 q2) e "commits" (lab 5 q2). A ideia: uma árvore em que cada nó pode ter qualquer número de filhos é representada com apenas dois ponteiros por nó, em vez de um vetor de filhos.

O padrão de código que se repete em todo exercício desse tipo

Uma vez que você entende que "percorrer todos os filhos de um nó" é andar por uma lista encadeada (pelo proximo_irmao), todo algoritmo vira uma combinação de duas ideias:

// (A) visitar UM nó e descer na árvore — recursão
void visita(NoArvore *no) {
    if (no == NULL) return;
    // ... trabalho no nó (pré-ordem) ...
    NoArvore *filho = no->primeiro_filho;
    while (filho != NULL) {          // (B) andar pelos irmãos — laço
        visita(filho);
        filho = filho->proximo_irmao;
    }
    // ... trabalho no nó (pós-ordem) ...
}

Isso resolve altura, contar, soma_valores, caminho, exibir — a única coisa que muda entre eles é o que você faz no "trabalho no nó" e onde (antes do laço = pré-ordem, depois do laço = pós-ordem).

DFS com pilha vs. BFS com fila (lab 3, questão 3)

A diferença entre os dois percursos não está em "visitar na ordem certa" — está em qual estrutura guarda os nós pendentes. Pilha = LIFO = desce fundo antes de voltar; fila = FIFO = varre nível inteiro antes de descer.

PassoPilha (DFS) após empilhar filhosFila (BFS) após enfileirar filhos
Visita raiz[B, C] (empilha C depois B → desempilha B primeiro)[B, C] (enfileira na ordem, tira B primeiro)
Visita B[D, E, C][C, D, E]
Visita próximoD (o mais fundo primeiro!)C (o mais raso primeiro!)
Estratégia

Ao empilhar os filhos de um nó na pilha, a ordem de inserção fica invertida na saída. Se a questão pede uma ordem de DFS específica, empilhe os filhos da direita para a esquerda para que o mais à esquerda seja desempilhado primeiro.

Aplicações reais (o que muda é só a struct)

  • Menu de navegação (lab 3 q1): cada nó é uma opção; navegar = seguir primeiro_filho; "voltar" precisa de ponteiro para o pai (ou pilha de navegação).
  • Taxonomia biológica (lab 3 q2): a árvore tem profundidade fixa (7 níveis); "contar espécies" é só contar nós com nivel == 6 — um pós-ordem simples.
  • Árvore de commits (lab 5 q2): TOTAL id soma a subárvore a partir de um nó qualquer, não da raiz — primeiro você precisa achar o nó pelo id (busca), depois somar (pós-ordem a partir dali).

3. Reconstruir uma árvore a partir de dois percursos

Lab 4, questão 1: dados pré-ordem e em-ordem, reconstrua a árvore e imprima o pós-ordem. Essa é a questão mais temida da prova porque parece mágica — mas é mecânica.

A ideia em uma frase

O primeiro elemento do pré-ordem é sempre a raiz da (sub)árvore atual. Procure esse valor no em-ordem: tudo à esquerda dele no em-ordem é a subárvore esquerda, tudo à direita é a subárvore direita. Repita recursivamente.

int preOrdem[], emOrdem[], indice = 0; // indice global/por referência

int posOrdem(int esquerda, int direita) {
    if (esquerda > direita) return; // sub-árvore vazia

    int raiz = preOrdem[indice++];      // consome o próximo elemento do pré-ordem
    int i = esquerda;
    while (emOrdem[i] != raiz) i++;     // acha a raiz dentro da faixa do em-ordem

    posOrdem(esquerda, i - 1);          // processa TODA a subárvore esquerda primeiro
    posOrdem(i + 1, direita);           // depois TODA a subárvore direita
    printf("%d ", raiz);                // só então imprime a raiz (é pós-ordem!)
}
Por que o índice do pré-ordem é global

Cada chamada recursiva consome exatamente um elemento do pré-ordem — a raiz da sua sub-faixa — e sempre na ordem em que eles aparecem no array, porque pré-ordem sempre visita "pai antes dos filhos" não importa de qual sub-árvore. Por isso o índice nunca pode "voltar": ele só anda para frente, consumindo um elemento por chamada.

4. Árvore Binária de Busca (ABB) — do zero

Propriedade: para todo nó, tudo na subárvore esquerda é menor, tudo na subárvore direita é maior. Essa única regra garante que o percurso em-ordem sempre sai em ordem crescente.

no* inserir_abb(no* raiz, int valor) {
    if (raiz == NULL) return criar_no(valor);      // caso base: achou o lugar vazio
    if (valor < raiz->valor)
        raiz->esq = inserir_abb(raiz->esq, valor);  // sempre reatribui o ponteiro!
    else
        raiz->dir = inserir_abb(raiz->dir, valor);
    return raiz;                                     // devolve a própria raiz, inalterada
}
Erro comum

Esquecer o raiz->esq = / raiz->dir = na recursão. Sem isso, o nó novo é criado mas nunca é conectado à árvore — a função "funciona" mas o nó se perde.

Maior e menor — sem recursão, com while

O menor valor está sempre no nó mais à esquerda possível; o maior, mais à direita. Não precisa de recursão nem de comparação de valores — é só "andar" até o ponteiro virar NULL.

no* menor(no* raiz) { while (raiz->esq != NULL) raiz = raiz->esq; return raiz; }
no* maior(no* raiz) { while (raiz->dir != NULL) raiz = raiz->dir; return raiz; }

Validar se uma árvore é uma ABB (lab 4, questão 2)

Erro clássico: comparar só o nó com seus filhos diretos. Isso não basta — um nó pode ser maior que o filho esquerdo mas ainda assim violar a regra com um neto. A solução correta carrega um intervalo (mínimo, máximo) permitido por chamada recursiva:

int eh_abb(int i, long long minimo, long long maximo) {
    if (i >= n || arv[i] == -1) return 1;                 // nó vazio: sempre válido
    if (arv[i] <= minimo || arv[i] >= maximo) return 0;   // violou o intervalo herdado
    return eh_abb(2*i+1, minimo, arv[i])      // filho esq.: herda teto = valor do nó
        && eh_abb(2*i+2, arv[i], maximo);     // filho dir.: herda piso = valor do nó
}
Por que isso funciona

Ao descer para a esquerda, todo valor da sub-árvore precisa ser menor que o nó atual — não só o filho direto. Por isso o maximo some para o valor do nó atual conforme você desce; o mesmo vale espelhado para minimo à direita.

K-ésimo menor elemento (lab 4, questão 5)

Como o em-ordem de uma ABB já sai ordenado, o k-ésimo menor é simplesmente a k-ésima parada do em-ordem. Não precisa ordenar nada: pare de contar quando chegar no k-ésimo nó visitado.

void kesimo(no* raiz, int k, int *contador, int *resultado) {
    if (raiz == NULL || *contador >= k) return;
    kesimo(raiz->esq, k, contador, resultado);
    (*contador)++;
    if (*contador == k) { *resultado = raiz->valor; return; }
    kesimo(raiz->dir, k, contador, resultado);
}

Sucessor e predecessor (lab 5: PROXIMO / ANTERIOR)

Essas operações apareceram na prova anterior — vale entender bem. O sucessor de um valor v (o próximo maior ou igual) e o predecessor (o anterior mais próximo) usam a mesma ideia de "melhor candidato visto até agora" enquanto você desce pela árvore comparando com v:

// próximo horário disponível >= h (sucessor-ou-igual)
int proximo(no* raiz, int h) {
    int melhor = -1; // -1 = "não existe"
    while (raiz != NULL) {
        if (raiz->valor >= h) { melhor = raiz->valor; raiz = raiz->esq; } // candidato; tente achar algo menor ainda >= h
        else raiz = raiz->dir;                                            // raiz->valor < h, só pode estar à direita
    }
    return melhor;
}
Estratégia

Pense em cada passo como "esse nó serve como resposta?" Se sim, guarde-o como melhor candidato e tente melhorar (ir para a esquerda, buscando algo ainda mais próximo de h). Se não, a resposta só pode estar do outro lado. ANTERIOR é o espelho exato disso: inverta >=/< e esq/dir.

5. Remoção em ABB — os 3 casos

Usada nas questões de "sistema de reservas" (lab 5 q1), "agenda de consultas" (lab 5 q3) e "dicionário" (lab 5 q4) — qualquer ABB com comando de remover.

no* remover_abb(no* raiz, int valor) {
    if (raiz == NULL) return NULL;                          // não encontrado: nada a fazer

    if (valor < raiz->valor)      raiz->esq = remover_abb(raiz->esq, valor);
    else if (valor > raiz->valor) raiz->dir = remover_abb(raiz->dir, valor);
    else {
        // achou o nó a remover
        if (raiz->esq == NULL && raiz->dir == NULL) {      // caso 1: folha
            free(raiz); return NULL;
        }
        if (raiz->esq == NULL) { no* t = raiz->dir; free(raiz); return t; }  // caso 2
        if (raiz->dir == NULL) { no* t = raiz->esq; free(raiz); return t; }  // caso 2

        no* sucessor = menor(raiz->dir);           // caso 3: sucessor em-ordem
        raiz->valor = sucessor->valor;             // copia o valor
        raiz->dir = remover_abb(raiz->dir, sucessor->valor); // remove o sucessor de onde estava
    }
    return raiz;
}
Degeneração — pegadinha teórica frequente

Inserir valores já ordenados (1, 2, 3, 4, 5…) transforma a ABB numa lista encadeada: cada nó só tem filho direito. Busca, inserção e remoção caem de O(log n) para O(n). Para n = 1.000.000: ~20 operações numa árvore balanceada contra até 1.000.000 numa degenerada. É exatamente para evitar isso que existem árvores auto-balanceadas (AVL, Rubro-Negra) — fora do escopo desta prova, mas é uma pergunta conceitual clássica ("por que usar AVL em vez de ABB comum?").

6. Árvore binária como array (formato heap)

Em várias questões (lab 4 q2–q5) a árvore chega como um vetor, não como ponteiros. A regra é sempre a mesma: para o nó no índice i, o filho esquerdo está em 2i+1 e o direito em 2i+2; -1 marca ausência de nó.

Percurso zigue-zague (lab 4, questão 3)

Nível 0 esquerda→direita, nível 1 direita→esquerda, nível 2 esquerda→direita... O jeito mais simples de implementar: faça um BFS normal nível a nível, e inverta a ordem de impressão apenas nos níveis ímpares (sem precisar de pilha dupla).

Simetria / espelho (lab 4, questão 4)

Uma árvore é espelho de si mesma quando, ao comparar o filho esquerdo de um lado com o filho direito do outro (cruzado), os valores batem recursivamente:

int eh_espelho(int heap[], int n, int esq, int dir) {
    int ve = (esq < n) ? heap[esq] : -1;
    int vd = (dir < n) ? heap[dir] : -1;
    if (ve == -1 && vd == -1) return 1;     // ambos vazios: simétrico até aqui
    if (ve != vd) return 0;                  // valores diferentes: não é espelho
    return eh_espelho(heap, n, 2*esq+1, 2*dir+2)   // esq-da-esq  vs  dir-da-dir
        && eh_espelho(heap, n, 2*esq+2, 2*dir+1);  // esq-da-dir  vs  dir-da-esq
}
Por que os índices são cruzados

Repare que a chamada compara 2*esq+1 (filho esquerdo do lado esquerdo) com 2*dir+2 (filho direito do lado direito) — é exatamente essa inversão que verifica "espelho" em vez de "igualdade simples".

7. Checklist final de pegadinhas

  • Confira a convenção de altura/profundidade do enunciado antes de responder questão objetiva.
  • Árvore vazia (NULL) ≠ árvore de um nó — todo caso base de recursão depende disso.
  • Em remover() de árvore genérica, salve proximo_irmao antes do free() — você já faz isso certo no seu código, mas é o erro nº 1 da turma.
  • Pré-ordem imprime o pai antes do laço de filhos; pós-ordem, depois. Trocar os dois é o erro mais comum ao montar árvore indentada no console.
  • Em ABB, o menor valor nunca está na raiz — está no nó mais à esquerda possível.
  • Validar ABB exige intervalo (mín, máx) herdado, não só comparação com os filhos diretos.
  • Grau só é "livre" em árvore genérica; em árvore binária é sempre ≤ 2.
  • Para o K-ésimo menor e para sucessor/predecessor, não existe atalho sem olhar a estrutura em-ordem — resolva em termos de "parar de contar" ou "melhor candidato até agora".
